## [0.1.0-alpha.2] - 2026-11-28

### 第三轮（音频底层 / 二维码 / 签名 / 后台 / 手册 / 组网与双向）

#### 音频
- 新增 native 音频库 mmaudio.dll（C++，desktop/native/，CI 在 windows-latest 用 MSVC 编译，静态 CRT，JNA 调用）：WASAPI 共享模式事件驱动采集/播放（采集设备缓冲 20 ms、播放 30 ms + 20 ms 环形缓冲，MMCSS「Pro Audio」线程）；打不开时自动回退 javax.sound（DirectSound），日志记原因；设置里可关掉「低延迟音频引擎」
- 按应用抓声音（Windows 10 2004 / build 19041+，AUDIOCLIENT_PROCESS_LOOPBACK）：输入通道新增「应用：xxx」（列出正在用声音的程序，如 w-okada、RVC、OBS，3 秒刷新，正在出声的排前面）与「电脑播放的所有声音（除 MicMask）」；可选「只抓这个程序（含子进程）」或「抓除它以外的所有声音」。RVC 的输出可以直接发到手机，不用占 VB-CABLE；目标没出声时补静音，不会误判断开
- 「电平跳、莫名声音小」：多声道下混改为只平均有信号的声道（不低于最响声道 −20 dB）。旧做法把所有声道相加再除以声道数：Voicemeeter VAIO（8 声道，通常只有前 2 声道有声）会被平均成 1/4（−12 dB），单边有声的立体声少 6 dB；WASAPI 路径浮点 → 16 位按 ×32767 限幅换算
- 发送卡加输入增益（−12 ~ +24 dB）与可选自动增益（AGC：目标约 −18 dBFS RMS，只在有声帧上调整，升 5 dB/秒、降 50 dB/秒，范围 −12 ~ +18 dB），带 −1 dBFS 限幅防爆音；电平表显示增益后的电平；日志每 10 秒记录增益前 / 后电平、AGC 当前值、限幅次数、音频引擎

#### 组网（EasyTier 全程 TCP 的日志）与双向
- 接收缓冲按传输方式与抖动自适应：UDP 30–150 ms、TCP 60–250 ms；目标同时覆盖「最近 10 秒最大到达间隔」（TCP 队头阻塞时音频成批到达）；断流补偿 UDP 最多 +60 ms、TCP 最多 +100 ms；日志记录传输方式、最大到达间隔、心跳超时
- 心跳超时 max(5 s, 8×最近 30 s 最大 RTT)（音频走 TCP 时至少 10 s，上限 20 s）、TCP 发送队列限长、UDP 探测在收到探测的同一个 socket 上回包并且不再要求 UDP 来源 = TCP 来源（EasyTier 代理 TCP 时 UDP 被全部丢弃、全程 TCP 的原因）：都在共享协议源码里（手机端同步修改），电脑端同步后直接使用
- 双向：同一台手机既连着电脑「接收」又要「发送」时，优先复用这一条会话（updateIntent 重发 CAPS），不再另开连接互相抢；电脑先连手机发送、手机在这条会话上回传声音时，电脑「接收」开着就播放；旧版手机没声明想收时仍另开连接（兼容）。界面显示「双向：同一条连接」，停止发送不影响接收
- 编码「跟随手机」改用共享协议的 followPeerCodec，去掉电脑端反射改字段；固定 Opus / PCM 用 followPeerCodec=false（复用会话时用 setTxCodec）

#### 二维码 / 链接
- 电脑「接收」显示二维码（micmask://link?h=地址列表&p=端口&c=配对码&id=设备ID&n=名称，与手机一致），可复制链接；地址含所有 IPv4 网卡（局域网在前、组网虚拟网卡在后）
- 「发送」支持粘贴 micmask:// 链接导入（剪贴板里有链接时一键导入）：并行探测链接里的每个地址，连最先通的；链接不带配对码时弹框输入

#### 统计 / 公告 / 赞赏墙（Beacon）
- 与手机同一后台、同一公告源。平台维度：渠道 ch=windows（后台目前没有平台字段），事件带 plat=windows；公告支持 platforms / plat 字段过滤（写了且不含 windows 的不显示）；公告频率 / 不再提示 / 强制阅读 / 阻断与手机一致，横幅公告显示在传音页顶部
- 后台地址 / App ID 用 secrets.BEACON_URL、BEACON_APP_ID，客户端 key 用 secrets.DESKTOP_BEACON_KEY；任一未配置时整体关闭，不发任何请求（自测验证）
- 启用时首次启动询问是否同意匿名统计；设置里可关
- 赞赏墙读同一后台：有名字才显示，空表显示「还没有赞助者」，加载失败显示「暂时无法加载」，不显示任何占位名字
- 更新检查仍只看 win-v* 标签

#### 代码签名
- desktop.yml：配置了 secrets.WINDOWS_CERT_PFX_BASE64 / WINDOWS_CERT_PASSWORD 时用 signtool（SHA-256 + RFC 3161 时间戳）签 mmaudio.dll、MSI、安装 EXE；或配置 Azure Trusted Signing（Artifact Signing）时用官方 action 签；都没有时跳过并在日志注明「未签名」。说明见 docs/desktop-signing.md

#### 其它
- 电脑版手册 docs/desktop-manual.md，「关于」页链接；desktop/README.md
- 自测新增：native 加载与回退、按应用抓声音、下混、增益 / AGC / 限幅、TCP 缓冲目标、链接与二维码、Beacon（未启用 0 请求 + 模拟后台）、双向复用
- 新依赖：JNA 5.15.0（Apache-2.0）、Nayuki QR Code generator 1.8.0（MIT）

### 第二轮修改（用户反馈 + 追加需求）

### 界面
- 改为桌面布局：左侧导航（传音 / 设置 / 关于 / 日志），传音页宽屏两栏（左发送、右接收；窗口窄于约 950 px 时上下排）；窗口默认 1100×720、最小 900×600、可调整大小；字号与间距按桌面密度；保留 miuix 风格与名称图标
- 中英文界面：与手机版同一套 tr 规则（中文即 key，英文表 resources/i18n/en-desktop.json，与手机版重叠的句子用同一译文）；设置里可选 跟随系统 / 简体中文 / English；日志不翻译
- 配对码一键复制、可选中复制；配对码输入框只收数字，粘贴「123 456」也行，剪贴板里有 6 位码时提示一键粘贴
- 本机设备名可在设置里改（默认「MicMask-PC-主机名」，用于 mDNS 与握手）
- 空状态、人话错误提示、按钮禁用原因、连接进度（正在连接… / 已连接 / 断开原因）

### 托盘与退出
- 托盘图标：点关闭默认最小化到托盘（第一次关闭时询问一次，设置里可改为直接退出 / 每次询问）；双击托盘图标打开窗口；托盘菜单：显示主窗口、开始/停止接收、开始/停止发送（显示当前状态与目标）、导出日志、退出
- 关到托盘时窗口真正销毁（释放 Skia/D3D 资源）并做一次 GC 让堆回缩；收发、自动连接在后台继续
- 关闭卡顿：旧版在界面线程里依次关闭每个网卡的 JmDNS（CI 实测单个实例关闭 >1.5 秒）再退出。现在真正退出时先立即隐藏窗口和托盘，再在后台并行清理（停止发送/接收、JmDNS 最多等 300 ms、上报），总超时 1.5 秒后直接结束进程；停止接收不再在界面线程里取消 mDNS 广播，播放线程不再 drain
- 启动参数 `--tray`：直接在托盘里启动；「启动时恢复接收」（默认开）

### 传音
- 输入通道：手机麦克风（= 接收到的手机声音，可直接当电脑麦克风输出到 CABLE Input，也可再转发给另一台手机）/ 系统默认（显示当前默认设备全名）/ 电脑麦克风 / 耳机麦克风 / 所有录音设备（全名 + 内置 / 3.5mm 耳机 / USB / 蓝牙 / 虚拟声卡 / 默认 标记，读 Windows 注册表端点属性，读不到按名字判断）；设备热插拔自动刷新，所选设备拔掉时回退系统默认并提示
- 发送卡实时输入电平（dBFS），没在发送时也预览所选音源；3 秒没信号提示「可能选到了静音设备」；日志每 10 秒记录发送输入电平
- 编码：跟随手机（默认，按手机的偏好选 Opus / PCM）/ Opus / PCM；旧版是发送方偏好决定，用户选了 PCM 就一直 PCM
- 发送端采集积压上限 60 ms（超过丢旧数据只留 20 ms）；手机回报的缓冲比本次会话最低值涨 60 ms 以上时在静音帧里少发几帧（每秒最多 50 ms）追平漂移；状态里显示手机缓冲与延迟
- 接收端改用自适应抖动缓冲：目标水位随抖动变化、断流后自动加 10 ms 余量；时钟漂移按 2 秒最低水位平滑裁剪（2 ms 交叉淡化），不再「涨到 180 ms 一刀砍回 60 ms」；断流淡出/淡入
- 已保存设备：扫描到的手机点一下即连接（需要配对码时弹框），成功后按协议设备 ID 记住；可重命名、删除、单独关自动连接
- 自动连接（默认开）：已保存的手机被 mDNS 发现或上次地址可达时自动连接发送，断线自动重连（2 秒起退避到 1 分钟）；手动停止后不再自动连，直到再次手动连接；配对码变了就停用旧码避免把手机锁住
- 本机地址列出所有网卡（含 EasyTier / Tailscale / ZeroTier 等虚拟网卡，标注），注明监听 0.0.0.0:47310；手填 IP 连接失败给出明确原因（超时 / 被拒绝 / 网络不通 / 握手无响应 / 配对码错 / 版本不兼容 / 协议不对）

### 日志
- 日志写文件：%LOCALAPPDATA%\MicMask\logs\micmask-desktop-yyyyMMdd.log，按天切分、单文件 4 MB，保留最近 7 个文件且不超过 20 MB；格式对齐手机端（时间 级别 [线程] {模块} 消息）
- 「日志」页按级别筛选、复制；「导出日志」（日志页、设置页、托盘菜单）：系统保存对话框（默认桌面）导出 micmask-desktop-logs-时间.zip（日志 + 系统信息：Windows/Java 版本、CPU/内存、音频设备、网卡地址、版本号、设置项），导出后在资源管理器里选中；配对码与密钥脱敏不写入
- 未捕获异常（含界面线程）写入日志

### 内存
- JVM 参数：SerialGC、-Xms16m、-Xmx256m（原 512m）、Min/MaxHeapFreeRatio 10/30（空闲时把堆还给系统）、MaxMetaspaceSize 192m、ReservedCodeCacheSize 64m、CICompilerCount 2、-XX:-UsePerfData
- 设置「界面渲染」：自动（显卡，默认）/ 软件渲染（CI 上少约 25–35 MB 工作集），重启生效
- 采集帧缓冲复用；日志内存只留最近 2000 条

### 自测
- `--smoke` 新增：i18n、注册表端点解析、采集积压、接收漂移（模拟手机时钟快 1%）、发送追帧、日志导出与脱敏、编码跟随、Opus 性能、本机地址；窗口阶段改为开真主窗口（含托盘）并测内存：开窗口 → 收发 10 秒 → 关到托盘 → 再开窗口 → 退出清理耗时（上限 1.6 秒）
- `--smoke --mem-only`：只跑窗口与内存阶段；CI 用它改 MicMask.cfg 对比 JVM 参数与 Skia 渲染后端（DIRECT3D / OPENGL / SOFTWARE）

## [0.1.0-alpha.1] - 2026-11-28

- 第一版骨架（Windows，Compose Desktop + miuix，名称与图标同手机版）
- 传音（MicMask Link v1，与手机共用协议源码）：加密（SPAKE2 配对码 + AES-GCM）、Opus / PCM、局域网自动发现（mDNS `_micmask._tcp`）
  - 接收：手机 → 电脑，播放到所选设备（默认 VB-CABLE「CABLE Input」，系统里多出麦克风「CABLE Output」）
  - 发送：电脑所选录音设备 → 开着「接收」的手机（手机注入 QQ / 微信 / 游戏）
- 附带 VB-CABLE 官方驱动包（VB-Audio Software，捐赠软件，vb-cable.com）：未安装时可一键以管理员身份安装
- 检查更新（GitHub Release 的 win-v 标签）；公告 / 赞赏墙 / 使用统计接口已接好，本版未启用
- 安装包瘦身：jlink 只带需要的 JDK 模块、release 构建开 ProGuard（只摇树不混淆）、只带 x64 Skia；改用 JDK 21 运行时（miuix 需要 Java 21）
- 自测：`MicMask.exe --smoke`（CI 每次在解包后的安装文件上跑：界面离屏渲染、加密/TLS、Opus 回环、mDNS、声卡枚举、真开窗口 3 秒）
- 已知限制：音频走 javax.sound（DirectSound），延迟比 WASAPI 高；还不能按进程抓声音；界面只有中文
